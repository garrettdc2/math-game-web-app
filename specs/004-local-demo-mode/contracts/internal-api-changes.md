# Contracts: Internal API Changes for Local Demo Mode

**Feature**: 004-local-demo-mode  
**Date**: 2026-04-06

## 1. Pipeline State API (existing, extended)

### GET /api/pipelines — Response changes

Each pipeline object in the response gains two new fields:

```
deploy_url:  string  — URL of deployed app ("" if not yet deployed)
deploy_mode: string  — "local" | "cloud" | "" (empty if not yet deployed)
```

These fields appear alongside existing fields (`task_id`, `title`, `stage`, `error`, `repo_name`, `workspace_path`, etc.). No existing fields are removed or renamed.

### POST /api/pipeline/start — Behavior change

When `git` service mode is "local":
- Factory creates `workspaces/{task_id}/` directory
- Initializes git repo in that directory (`git init`)
- Sets `workspace_path` on the pipeline state

When `git` service mode is "cloud":
- No change to current behavior (workspace created by agents)

## 2. Event Ingestion Webhook (existing, extended)

### POST /api/events/ingest — New event types

The deployer agent (or local deploy manager) can emit:

```
event: "deploy:local"
task_id: string
detail: string  — JSON: { "url": "http://localhost:3001", "port": 3001, "mode": "local" }
```

```
event: "deploy:cloud"
task_id: string
detail: string  — JSON: { "url": "https://app-name.netlify.app", "mode": "cloud" }
```

Both events update `deploy_url` and `deploy_mode` on the pipeline state.

## 3. Service Modes API (new)

### GET /api/service-modes

Returns the current service mode configuration. Used by the dashboard to display mode indicators.

**Response:**

```
{
  "git": "local" | "cloud",
  "deploy": "local" | "cloud", 
  "database": "local" | "cloud"
}
```

This endpoint is read-only. Modes are determined at startup from environment variables and cannot be changed at runtime.

## 4. Agent Memory File Contract (existing, extended)

### Service Modes Block

Added to the memory file header when the factory agent writes initial context:

```
## Service Modes
- git: {local|cloud}
- deploy: {local|cloud}
- database: {local|cloud}
- workspace: {absolute path to workspace directory}
```

All downstream agents read this block to determine their behavior. This is a convention enforced by the factory agent's skill file, not a schema-validated structure.

## 5. Agent Settings Generation Contract (new)

### Input: Environment variables

```
GITHUB_TOKEN    — if set: include github MCP server for dev, reviewer, tester, architect, deployer
NETLIFY_TOKEN   — if set: include netlify MCP server for deployer
SUPABASE_TOKEN  — if set: include supabase MCP server for deployer
```

### Output: Per-agent `.claude/settings.json` files

Generated by `scripts/generate-agent-settings.ts` before gateway startup. Each file contains:
- `permissions`: Always includes base tools (Read, Write, Edit, Bash, Glob, Grep). Adds `mcp__github__*`, `mcp__netlify__*`, `mcp__supabase__*` only when corresponding token is available.
- `mcpServers`: Only includes server entries for tokens that are present.

### Invariant

The settings generation script MUST be idempotent. Running it multiple times with the same environment produces identical output.
